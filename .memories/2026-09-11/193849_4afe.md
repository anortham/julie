## Task 4: replaced the xtask bucket runner with three fixed tiers

**WHAT:** `cargo xtask test dev|dogfood|full` now runs a fixed command list through `CommandExecutor`; every other tier word prints `expected \`cargo xtask test <dev|dogfood|full>\`` and exits 2. Deleted the manifest (`test_tiers.toml`), `changed`, `inventory`, prebuild, budget, coverage, and timeout-multiplier machinery. `xtask/` went from 11,470 to 2,233 lines.

**WHY:** One `cargo nextest run --workspace` finishes in about 10 s versus 50 s for the old `dev` tier; the bucket manifest cost more than it saved.

**HOW:**
- `xtask/src/cli.rs`: `Tier` enum, `CliCommand::Test(Tier)`, usage error on bad tier.
- `xtask/src/runner.rs`: `DEV` and `DOGFOOD` command lists, `tier_commands`, `run_tier` printing `RUN`/`PASS`/`FAIL`/`SUMMARY`, `ProcessCommandExecutor` inherits stdio.
- `xtask/src/process.rs`: `manifest_command` renamed to `shell_command`; quoted filtersets survive.
- `.config/nextest.toml`: dogfood test group capped at 6 threads.
- `xtask/tests/tier_tests.rs` (fake executor), `dispatch_tests.rs` (real binary with fake cargo), `docs_contract_tests.rs` rewritten to the new doc strings.

**IMPACT:** `cargo xtask test dogfood` green in 14.4 s. `cargo xtask test dev` fails only on the two docs-contract tests, which Task 5 turns green by rewriting CLAUDE.md, AGENTS.md, README.md, and docs.
