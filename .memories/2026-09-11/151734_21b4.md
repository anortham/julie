## Store open errors now name the store directory

**WHAT** — Both checkout-store openers wrap the non-mismatch `Err` arm with the store path:
`src/tools/workspace/indexing/store_open.rs::open_or_recreate` and
`crates/julie-runtime/src/workspace/mod.rs::open_or_recreate_store`.

**WHY** — Task 1 removed the self-heal delete, so every non-mismatch open failure now propagates.
No layer below added the path: `julie-facts::FactsStore::open` returns raw rusqlite errors, and
`CheckoutStore::open` adds context only around `create_dir_all`. An operator reading
`src/handler.rs:1209` (`Failed to check indexing status: {e}`) saw only "database is locked" with
no directory.

**HOW** — One arm in each opener: `Err(err) => Err(err).with_context(|| format!("open checkout store {}", <dir>.display()))`.
The `VersionMismatch` downcast guard sits before it, so the delete-and-reopen path is unchanged.
`anyhow` downcast still reaches through a context layer, so no caller loses type information.

**IMPACT** — A locked, corrupt, or unreadable `facts.sqlite` now reports which directory failed.
New test `open_failure_error_names_the_store_dir` writes non-sqlite bytes into `facts.sqlite` and
asserts both openers put the directory in the error text. It runs in 7ms; no 5s busy timeout needed.
