## Task 2: status reads checkouts through the non-destructive opener

**WHAT** — `checkout_status` in `src/tools/workspace/commands/registry/status.rs` now calls
`handler.checkout_store_for_workspace(&workspace_id, &root)` instead of the
`store_open::store_for_workspace` helper. The unused import is gone. A new test
`status_over_a_locked_checkout_reports_not_loaded_and_deletes_nothing` lives in
`src/tests/tools/workspace/store_open.rs`.

**WHY** — The index-hygiene plan (decision item 2) says `/status` must never open a
checkout through a path that can delete it. One opener on the read path makes that
property provable in one place.

**HOW**
- `checkout_store_for_workspace` already opens through `open_or_recreate`, caches the
  store, and never caches a rebuilt empty store.
- The test builds a real store for a temp checkout, registers one row in a temp
  `daemon.db`, holds `PRAGMA locking_mode = EXCLUSIVE` on its `facts.sqlite`, then runs
  `manage_workspace` `status` with no `workspace_id`.
- `CheckoutStatus` has no `store_status` field. The "not loaded" state shows up as
  `tantivy == "absent"`, `symbol_count == 0`, `blob_count == 0`, `last_write_at == null`.
  The test asserts those plus the survival of `facts.sqlite` and its symbol count.

**IMPACT** — The test was already green before the swap: Task 1 removed the delete
branch from `store_for_workspace`, so status was no longer destructive through that
route. The swap removes the last indirect route and the test is now the regression guard
for both. `cargo check --workspace --all-targets` reports zero errors.
