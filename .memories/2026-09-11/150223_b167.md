## Task 1: a checkout store is deleted only on a version mismatch

**WHAT** — Both store openers now delete `indexes/<id>/` only when `CheckoutStore::open` returns the typed `VersionMismatch`. Three duplicate delete layers are gone.

- `src/tools/workspace/indexing/store_open.rs` — `open_or_recreate` matches `err.downcast_ref::<VersionMismatch>()`; every other error propagates. `store_for_workspace` drops its second delete-and-retry branch and returns the error from `checkout_store_for_workspace`.
- `crates/julie-runtime/src/workspace/mod.rs` — `open_or_recreate_store` gets the same guard.
- `src/startup_repair_plan.rs` — both `delete_store_dir` calls removed; a failed open or facts read returns the error. A real version mismatch is still caught earlier by `store_engine_mismatch`.
- `src/request_engine/runtime_factory.rs` — `initialize_recovering_store` calls `initialize_workspace_with_force(None, false)` once, maps the error, and returns `RequestFailure::internal` when the workspace is still `None`. No delete, no retry. Made `pub(crate)` so the test can reach it.

**WHY** — The service deleted live indexes on transient open failures. A locked or busy `facts.sqlite` cost the user a full reindex.

**HOW** — `VersionMismatch` (`crates/julie-index/src/checkout_store/mod.rs:38`) is public and reaches `julie-runtime`. `CheckoutStore::open` propagates it from `open_facts` with no extra context wrapper, so a single `downcast_ref` classifies it.

**Discovery** — The brief's `BEGIN EXCLUSIVE` lock recipe does not work: `facts.sqlite` runs in WAL mode, and in WAL an exclusive transaction does not block readers. `PRAGMA locking_mode = EXCLUSIVE` plus one read does block every other connection. The test uses that.

**IMPACT** — `delete_store_dir` now appears only in `store_open.rs` (its definition and the one mismatch call). The authorized deletes stay: `handler.rs` force reindex, `refresh.rs` rebuild, `cleanup.rs` sweep.
