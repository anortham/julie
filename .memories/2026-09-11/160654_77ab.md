## Task 3 fix round 2: the shim reaps the service it spawns

**WHAT** — `spawn_detached_service` (`src/service/client.rs`) now hands the `Child` to `reap_in_background`, a detached thread that calls `wait()`. Before this, the `Child` was dropped and the service stayed an unreaped zombie child of the shim after a hard kill.

**WHY** — `pid_alive` on macOS and the BSDs uses `kill(pid, 0)`, which reports a zombie as alive. Combined with the new record guard in `try_connect`, a hard-killed service left a `service.json` record that nothing removed, so the shim never respawned. Round 1 fixed only Linux, by reading `/proc/<pid>/stat`.

**HOW** — Reaping the child at the source makes the pid disappear on every unix, so `kill(pid, 0)` reports it dead without any per-platform `/proc` inspection. Three lines. The Linux `/proc` state check stays, because a record can name a pid this process never spawned.

**IMPACT** — A hard-killed service self-heals again on macOS and the BSDs. Only a service started by another live shim is still missed.
