## Task 5: hermetic tests and a database-derived indexes dir

**WHAT**
- `.cargo/config.toml` `[env]` now sets `JULIE_HOME = { value = "target/test-julie-home", relative = true }`. No `force`, so an exported `JULIE_HOME` still wins.
- `DaemonDatabase` keeps the `path` it was opened from, and gains `path()` plus `indexes_dir()` (`<db parent>/indexes`).
- `registry_store_for` builds the store from `daemon_db.indexes_dir()`. The `RegistryPaths::try_new()` call is gone.

**WHY**
A test that opened a temp `daemon.db` still got its indexes directory from `RegistryPaths`, which pointed at the developer's real `~/.julie`. The `manage_workspace list` cleanup sweep then deleted real index directories that no temp registry knew about.

**HOW**
- The store now derives its indexes directory from the database it holds, so a temp registry can only sweep its own tree.
- Production behaviour is unchanged: every non-test `DaemonDatabase::open` uses `<julie_home>/registry.db`, so `indexes_dir()` equals `RegistryPaths::indexes_dir()`.
- `with_env` and `EnvGuard` in `src/tests/registry/paths.rs` became `pub(crate)` so other test modules can point `JULIE_HOME` somewhere safe.

**IMPACT**
- `cargo` test runs no longer read or write the developer's `~/.julie`.
- Task 6 (cleanup sweep at service start) can rely on the fixed helper.
