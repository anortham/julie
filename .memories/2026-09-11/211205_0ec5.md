## Task 6 end-to-end passed; fixed missing MCP instructions in the service

- **WHAT:** The packed Linux archive (julie-server 8.0.0 plus sidecar 0.1.0) ran through the plugin's `run.cjs` with its own `JULIE_HOME`: initialize returned 8.0.0, `fast_search` returned 6 hits, the embedding child reported `state: ready` on the first poll with the packed sidecar found beside the packed binary, and `service stop` cleaned up. One invariant failed: `initialize` had no `instructions` field.
- **WHY:** `src/service/mcp.rs` built `McpAdapter::new(engine, None)` without `.with_instructions(...)`, so the service, and therefore every stdio shim client, dropped the routing text. Only the old in-process stdio path set it.
- **HOW:** TDD. New test `initialize_over_http_carries_the_agent_instructions` in `src/tests/service/mcp_http.rs` (RED, then GREEN). `mcp_adapter::AGENT_INSTRUCTIONS` is now the one `include_str!` of `JULIE_AGENT_INSTRUCTIONS.md`; the handler and the service both use it.
- **IMPACT:** Every MCP client gets the instructions again. Deferred (plugin): `run.cjs findArchive` takes the first `readdirSync` match, so two archives for one target would pick by directory order; the update workflow replaces `bin/archives/` wholesale, so shipped plugins hold one per target. Also `bin/archives/` is not git-ignored in the plugin; the local 8.0.0 archive stays untracked and must not be committed.
