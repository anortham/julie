## Item 3 baseline measured and design written

**WHAT**: `docs/plans/2026-09-11-test-speed-design.md` (untracked on main, moves to the task worktree after approval). Full baseline table, cause analysis, design, acceptance criteria.

**WHY**: The owner said 90 percent of time goes to waiting on tests. The numbers show the wait is the serial bucket runner, `changed` falling back to `dev`, the dogfood graph build in an unoptimized crate, and three 10 s waits. Not compile time: the edit loop is 3.5 s.

**HOW**: Measured on main `ab6b8077` with cargo timings, `-Ztime-passes`, a probe worktree, one whole-workspace nextest run, a coverage script over `cargo nextest list` against `xtask/test_tiers.toml`, and an `eu-stack` sample of the 8 s store open (`Graph::build` -> `resolve_reexport` -> `direct_targets` scanning 4,201 imports per reference).

**IMPACT**: Design awaits owner approval because it deletes the bucket system the owner built (manifest, tiers, changed, inventory, CLAUDE.md sections). Side findings: `cargo xtask test inventory` is broken for `-j 1` and `--test-threads` commands; `-j 1` never serialized tests; a test binary built in a worktree that shares `target/` bakes that worktree's path into `CARGO_MANIFEST_DIR` and the main checkout reuses it (fixture path failures until a rebuild).
