## Task 3: restart waits on the pid; only the owner removes the record

**WHAT** — Added `discovery::pid_alive(pid)` and wired it into the three places that treated `service.json` as disposable.

- `src/service/discovery.rs` — `pid_alive`: pid 0 is dead; Linux reads `/proc/<pid>`; other unix uses `libc::kill(pid, 0)`; Windows uses `OpenProcess` + `GetExitCodeProcess` from the already-declared `windows-sys`. No new dependency.
- `src/service/client.rs` — `try_connect` removes the record only when the pid is dead. A live pid returns `Unavailable("service <pid> is shutting down")`.
- `src/service/mod.rs` — `serve` removes the record only when the record on disk carries this process id.
- `src/main.rs` — `service restart` polls `pid_alive(record.pid)` every 100 ms for up to 30 s after `post_shutdown`, then calls `connect_or_start`.

**WHY** — A stale or shutting-down service used to lose its record to any client that failed one `/status` call, and a service that did not own the record still deleted it. Restart also raced the old process.

**HOW** — TDD. Three tests: two in `src/tests/service/client.rs`, one in `src/tests/service/control.rs`.

**IMPACT** — The `Running` test harness drops its temp home inside `finished()`, so the old `shutdown_stops_the_service_and_removes_the_record` assertion was vacuous: the record file was gone with the directory. Both shutdown tests now start the service over a temp home the test owns (`OwnedService` in `control.rs`), so the record assertions are real.
