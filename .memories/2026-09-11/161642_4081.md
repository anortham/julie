## Task 4: service log under the Julie home

**WHAT** — The machine service now writes its log to `$JULIE_HOME/logs/julie-service.log.<date>`, and `GET /status` reports that path in a new `log` field.

**WHY** — Before this, the unbound service runtime built its `ProjectLog` from a throw-away `tempfile::tempdir()`, so service-level tool calls logged into a temp directory that disappears. Operators had no service log to read.

**HOW**
- `RegistryPaths::logs_dir()` (`crates/julie-core/src/paths.rs`) returns `<julie_home>/logs`.
- `ProjectLog` gained a `file_prefix` field plus `in_dir(log_dir, file_prefix)`; `new` delegates with the `julie.log` prefix, so per-project logs are byte-for-byte unchanged. `current_path(log_dir, prefix)` gives today's file name to callers that do not hold the logger.
- `RuntimeFactory::create_unbound_runtime` replaces the handler's `project_log` with `ProjectLog::in_dir(registry_paths.logs_dir(), SERVICE_LOG_PREFIX)`.
- `status` in `src/service/http.rs` now returns `Json<Value>`: it serializes the `StatusDocument` and inserts `log`. This keeps `src/service/status.rs` out of the change, which Task 4 does not own.

**IMPACT** — `tail -f $JULIE_HOME/logs/julie-service.log.*` works, and `/status` tells an operator which file to read. Per-project `.julie/logs/julie.log.<date>` behaviour is untouched.
