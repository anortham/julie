## Task 1 fix round 1: route every checkout-store open through `open_or_recreate`

**WHAT**
- `src/handler.rs:1383` (`checkout_store_for_workspace`) now calls `open_or_recreate` instead of `CheckoutStore::open`.
- New test `version_mismatch_on_a_secondary_checkout_is_rebuilt` in `src/tests/tools/workspace/store_open.rs`.
- Doc comments on `checkout_store_for_workspace` and `store_for_workspace` state the mismatch rule.

**WHY**
The first commit (2870f423) removed the delete-and-retry branch from `store_for_workspace`, so the call fell straight through to `checkout_store_for_workspace`. That method opened with `CheckoutStore::open`, which returns the typed `VersionMismatch` error and nothing above it classified the error. After a `SEMANTIC_INDEX_ENGINE_VERSION` bump, every secondary checkout would hard-error on status, index, incremental, and pipeline persistence until an operator ran rebuild. CLAUDE.md states the invariant: a schema or engine version mismatch deletes `indexes/<id>/` and reindexes.

**HOW**
One line in the handler. The delete stays inside the single approved opener, so all callers of `checkout_store_for_workspace` self-heal: `store_for_workspace`, health checker readiness, snapshot, edit_file, embeddings. `fast_refs checkout_store_for_workspace` proved the caller list (24 references).

**IMPACT**
- A version-mismatched secondary checkout rebuilds instead of failing.
- A locked or corrupt store still returns the error with the directory intact; that is unchanged.
- `cargo nextest run --lib tests::tools::workspace::store_open` — 4 passed.
- `cargo check --workspace --all-targets` — clean.
