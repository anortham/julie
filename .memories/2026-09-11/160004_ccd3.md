## A zombie pid now counts as dead in `pid_alive`

**WHAT** — The Linux branch of `service::discovery::pid_alive` reads `/proc/<pid>/stat` and returns `false` when the state field is `Z`. It used to only check that `/proc/<pid>` exists.

**WHY** — `spawn_detached_service` drops the `Child` without waiting, so the machine service stays an unreaped child of the shim. After a `SIGKILL`, an OOM kill, or an abort, the pid became a zombie. `/proc/<pid>` still exists for a zombie, so `try_connect` kept `service.json` and returned "service <pid> is shutting down" forever. The shim never respawned and `service restart` waited the full 30 s and then failed. Recovery needed a manual delete of `service.json`.

**HOW**
- The state field is read after the last `)` in `stat`, because the command name can hold spaces and parentheses.
- A missing or unreadable `stat` file is dead. An unparsable state is alive.
- The check is on the pid, not on an owned `Child`, so it is correct for a service that another shim started.
- The test uses `libc::waitid` with `WEXITED | WNOWAIT`. It blocks until the child exits and does not reap it, so the test needs no sleep and no poll loop.

**IMPACT** — The shim self-heals again after a hard kill. The non-Linux unix branch still has the same bug, because `kill(pid, 0)` reports a zombie as alive on macOS and the BSDs.
