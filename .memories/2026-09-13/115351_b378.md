## Fast-search paging count corrected

### WHAT

The Plan 4 worktree now corrects `fast_search` continuation metadata after file-hit collapse.

### WHY

Page one collapsed overlapping file-level hits from three raw rows to two visible rows, but retained the pre-collapse total of three. The response therefore advertised an offset-2 continuation whose next page was empty.

### HOW

A focused regression test, `fast_search_does_not_continue_after_collapsing_file_hits`, was added first and reproduced the erroneous continuation. The shared execution path now resets `execution.total_results` after `collapse_covered_file_hits`, so paging metadata matches visible post-collapse results. The exact RED/GREEN cycle passed.

### IMPACT

Real agents no longer receive a false next-page instruction for this result shape. This closes the defect found during Claude and Codex client qualification before the native branch is frozen and retried.
