## Native semantic probe request mode corrected

### WHAT

The cross-platform native probe now places `semantics: required` in the actual `fast_search` tool parameters and removes the misleading redundant CLI-only switch. Failure output preserves the last exit, bounded stdout/stderr, and readiness evidence.

### WHY

The generic CLI `--semantics required` did not become the tool request's readiness mode. The probe omitted the schema's `semantics` field while requiring the response to report `mode=required`, so it would time out even when the native semantic hit and coverage were healthy. Existing direct CLI evidence showed a CLI-level `--semantics off` invocation still returned request readiness mode `auto`.

### HOW

A small `search_params` function exposes the real request contract. Its self-test was changed first and failed because required mode was absent; the field was then added and the exact self-test passed. No third hosted run or second real model diagnostic was performed.

### IMPACT

The harness logic is locally corrected and future native runs will exercise required semantics correctly. The authorized native retry budget is exhausted, so macOS/Windows qualification remains incomplete until the owner explicitly approves another run.
