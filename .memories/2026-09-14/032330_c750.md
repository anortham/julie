## WHAT

- Fixed Windows workspace-root detection so an ancestor user-profile `.vscode` directory cannot capture an explicitly requested unmarked directory.
- Added a Windows `CreateProcessW` service launcher with handle inheritance disabled, preventing detached services from retaining Nextest output pipes.
- Serialized `tests::service::process` through a dedicated Nextest test group and normalized the version-mismatch path expectation to native separators.
- Added regression coverage for ancestor `.vscode` capture.

## WHY

The first Windows full gate resolved explicit workspaces to `C:/Users/alann` because that profile contains `.vscode`. After that fix, service-process tests hung because a detached Windows grandchild inherited the test harness output handles, so Nextest waited after the test parent exited.

## HOW

- `.vscode` now counts only at the requested start path; VCS and language project markers still participate in ancestor traversal.
- Windows service spawning calls `CreateProcessW` with `bInheritHandles = FALSE`, `DETACHED_PROCESS`, and `CREATE_NEW_PROCESS_GROUP`, then closes the returned process/thread handles.
- Non-Windows spawning retains `std::process::Command` and background reaping.
- A serial Nextest group prevents these machine-service lifecycle tests from racing over shared process behavior.

## IMPACT

Focused Windows compiler and test verification passes. No test-owned `julie-server.exe` remains. The Windows `cargo xtask test full` branch gate is still incomplete because the permitted retry found another failure/hang; project policy requires explicit owner approval before a third broad run.
