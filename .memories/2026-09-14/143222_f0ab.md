## WHAT

Fixed the Windows v8 release blockers across service spawning, workspace discovery, and test qualification. Windows service startup now uses `CreateProcessW` with handle inheritance disabled; root detection no longer lets an ancestor `.vscode` capture an explicit workspace. Windows-specific test fixtures now isolate derived indexes, keep and stop fixture services deterministically, avoid unnecessary MCP startup for standalone CLI scenarios, use repository-local temp storage for heavy Tantivy writes, normalize Windows command/TOML paths, and assert stable behavioral contracts instead of scheduler timing.

## WHY

The Windows full gate exposed executable-handle inheritance, editor-marker root capture, shared `.julie` fixture state, short-lived fixture services, system-temp Tantivy interference, shell quoting, TOML backslash escaping, and load-sensitive timing assertions. Each failure passed alone or failed only under Windows concurrency, showing non-hermetic qualification behavior rather than one product algorithm defect.

## HOW

Applied TDD with exact RED/GREEN tests, then repeatedly ran the owner-approved full Windows gate as new late failures surfaced. Preferred unique fixture roots and deterministic cleanup over sleeps, retries, broad serialization, or weakened assertions. An independent Miller-first review reported no material findings.
