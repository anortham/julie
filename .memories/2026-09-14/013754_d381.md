## Windows detached-service handle inheritance

### WHAT

Updated `src/service/client.rs` in the release worktree to launch the Windows detached service with an explicit STARTUPINFOEXW handle list containing one inheritable `NUL` handle used for stdin, stdout, and stderr.

### WHY

A replacement service inherited `Command::output()` capture handles on Windows, so `service restart` could keep the caller's output pipes open and hang.

### HOW

The spawn now creates inheritable `NUL`, configures `STARTF_USESTDHANDLES`, creates a one-entry `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`, calls `CreateProcessW` with `EXTENDED_STARTUPINFO_PRESENT`, and closes the process/thread/NUL handles plus deletes the attribute list on every path.

### IMPACT

The existing restart regression remains unchanged and is ready for one clean-guest Windows GREEN run. Local formatting and `cargo check` pass with existing warnings.
