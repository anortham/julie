## Fixed system-tier target-workspace and semantic-version tests

### WHAT
- Search of a target workspace no longer returns `Workspace not indexed yet` after a successful index.
- `plan_primary_workspace_repair` reports `SemanticVersionChanged` when `facts.sqlite` meta is stale.
- Live-surface test no longer reads deleted `navigation/target_workspace.rs`.

### WHY
After Task 13, facts live at `indexes/<id>/{facts.sqlite,tantivy/}`. The tests already wrote that layout via `ManageWorkspaceTool`. The search gate still required `workspace_registry.json` (never written in stdio). The planner used the already-open store and never re-read `meta.engine_version`.

### HOW
- `check_workspace_store_readiness` and `ToolContext::snapshot` open `indexes/<id>/facts.sqlite` when the registry lookup fails.
- `store_engine_mismatch` reads `facts.sqlite` meta on disk before the planner uses the in-memory store.
- Dropped the missing julie-tools navigation file from the live-surface list.

### IMPACT
Stdio target-workspace search works after index. Engine-version drift is visible to startup repair. Integration slice is green (107 tests).
