## Task 11 fix: search readiness uses the facts store

### WHAT
`HealthChecker` search gating now reads `CheckoutStore` / `StoreStatus` instead of `symbols.db`. A facts-only index with graph symbols is FullyReady when Tantivy is present, else SqliteOnly. Zero symbols or failed open is NotReady.

### WHY
Lead `cargo xtask test dev` failed: standalone CLI search after index returned "Workspace not indexed yet" because `canonical_store` still used empty `symbols.db` stats.

### HOW
- `build_data_plane` fills `canonical_store` from `CheckoutStore::status` (graph symbols, paths, edges, vectors, facts_bytes).
- Overlay the Tantivy projection to Ready/Current only when the store has symbols and `TantivyState::Present`.
- Target `check_workspace_store_readiness` uses the same store counts.
- `readiness_from_data_plane` treats zero symbols as NotReady.

### IMPACT
`test_run_cli_tool_standalone_definition_search_uses_bootstrapped_index` is green. Unparked auto-activate search. Parked two rebound health-dashboard tests for Task 12.
