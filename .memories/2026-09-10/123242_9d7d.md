## Task 3: Snapshot, CheckoutStore, facts projection, ToolContext::snapshot

**WHAT**
- `julie-index`: `snapshot::Snapshot` (graph + pinned searcher + fields + vectors + read-only facts access + `file_text`), `checkout_store::CheckoutStore` (`open`, `open_with_ram_index`, `current`, `apply(changes, guard)`, `rebuild_tantivy_if_needed(guard)`, `status`), `search::projection::from_facts` (documents from `FileRows` + file text, same 21 fields), `vectors::VectorSet::empty()`.
- `julie-facts`: `FactsStore::open_read_only`.
- `julie-context`: `ToolContext::snapshot(&WorkspaceTarget) -> Arc<Snapshot>`; `julie-test-support`: `SnapshotFixture::from_tree` + `FakeToolContext::with_snapshot_fixture`.
- Double write: watcher queue processing (`processing.rs`) and indexing pipeline (`pipeline_persistence::apply_checkout_store`) write the store beside the old SymbolDatabase/SearchIndex under the same gate.

**WHY** The one seam between storage and tools for Tasks 4-9; old path stays until Task 13.

**HOW / decisions**
- Old `SearchIndex` already owns `<index_dir>/tantivy/` (writer lock + old doc ids), so the new store lives at `<index_dir>/store/{facts.sqlite,tantivy/}` during the transition (`checkout_store::STORE_DIR`). Task 13 moves it up.
- `rusqlite::Connection` is not `Sync`, so `Snapshot::facts()` opens a read-only connection per call instead of sharing one behind a mutex (readers never wait).
- Fixture facts live in a temp file (not `in_memory()`), Tantivy in RAM.
- Tantivy writer is created per batch and released after commit.
- Watcher wiring goes through `IncrementalIndexer::with_store` and `QueueRuntime` rather than changing the 80-call-site handler signatures; pipeline gets the gate guard threaded through `index_workspace_files` and `run_indexing_pipeline`.

**IMPACT** Worker scope green: julie-index checkout_store (6), julie-test-support (13), durable_roots, julie-runtime watcher_handlers (20), `cargo build`.
