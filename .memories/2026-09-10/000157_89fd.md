## Task 3 fix round 1: MCP roots bootstrap deleted; typed workspace failure restored

### WHAT
- `src/handler.rs` 2224 -> 1890 lines. Deleted the roots resolution gate, client-roots capability and snapshot state, `list_roots_from_peer`, root-URI parsing, both roots reconcile paths, `on_roots_list_changed`, the roots branch of `on_initialized`, and the teardown-and-reload branch of `initialize_workspace_with_force`.
- `ensure_primary_workspace_for_request(&self)` now only binds the startup hint once when the handler was built unbound.
- `new_with_shared_workspace_startup_hint` always binds the given workspace id (no Cwd deferral).
- Deleted `src/tests/registry/roots/` (2682 lines with `roots.rs`), the roots answerer in `src/tests/helpers/mcp.rs`, `deferred_explicit_targets.rs`, and eight roots-driven cases in other test files.
- `BindingResolver::resolve` treats a selector that is neither a registry row nor a path on disk as a workspace id for the tool layer and binds the process workspace instead of failing with `WORKSPACE_MISSING`.
- `RequestEngine::dispatch` maps a `WorkspaceResolutionFailure` from a tool to `INVALID_ARGUMENTS` with the `<tool> failed: ` prefix, matching the rmcp tool wrappers.

### WHY
MCP 2026-07-28 is stateless; the service never receives client roots, so the per-session roots bootstrap was code for a state that cannot exist. The typed "Workspace 'X' not found. Did you mean 'Y'?" failure was lost when the request engine landed (e7529824): the engine rejected unknown ids as missing paths before any tool ran, and its generic error mapping turned tool-level resolution failures into `TOOL_ERROR`.

### HOW
- Root cause of the deep_dive failure was proved by running the test at `a3ef3e5a` (phase start) and `386f49d6`: it fails identically at both, so it predates Phase 2 and came from the request engine commit.
- Fix: `is_unknown_selector` in `binding.rs` plus a `workspace_resolution_failure_kind` arm in `dispatch.rs`.

### IMPACT
- `cargo build` green; `tests::tools::workspace::global_targeting` 19/19; `tests::dashboard` 90/90; `cargo nextest run -p xtask` 179/179; `tests::registry` 93/93; `tests::request_engine` 19/19; the single deep_dive test passes.
- Sensitive-root rejection and workspace precedence stay covered by `src/tests/request_engine.rs`, so no roots test needed to move.
