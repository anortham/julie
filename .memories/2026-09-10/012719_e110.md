## Task 8: manage_workspace rebuild + status; retired register, clean, stats

**WHAT**
- `ManageWorkspaceOperation::OPERATIONS` is now `index, list, open, remove, refresh, health, rebuild, status, recover_edit, recover-edit, dashboard`.
- New `src/tools/workspace/commands/registry/status.rs` (197 lines): `CheckoutStatus` struct plus `handle_status_command`. Computed on request from the registry row, `indexes/<id>/` on disk, and the loaded workspace's watcher. Returned as text plus `structuredContent.checkouts`.
- `handle_rebuild_command` in `registry/refresh.rs`: under the mutation guard, delete `indexes/<id>/`, run the force index path, prefix the message with `Rebuilt <root>`.
- `GET /status` now carries `checkouts: Vec<CheckoutStatus>`; the handler runs `manage_workspace status` through `RequestEngine::execute` (no handler reach-in).
- Deleted `handle_register_command`, `handle_clean_command`, `handle_stats_command`; renamed `refresh_stats.rs` -> `refresh.rs`, `list_clean.rs` -> `list.rs`, `register_remove.rs` -> `remove.rs`.
- `IncrementalIndexer` gained `is_running()` (replaces the test-only getter) and `last_file_event_at()` (max of the 2s dedup map).
- CLI: `WorkspaceArgs` lost the dead `--name` flag; standalone refusal list is now `open | remove | refresh`.

**WHY**
Design section 14.2 names `rebuild` and `status` as the checkout operations; `open` covers `register`, `list` prunes so `clean` is redundant, `status` supersedes `stats`. Design section 10 wants every checkout on the status page.

**HOW / decisions**
- Unbound runtime (`runtime_factory.rs`) now gets `in_process_index_root = registry_paths.workspace_index_dir(<temp-root-id>)` so `workspace_index_dir_for(id)` resolves to the service's `indexes/<id>` for unbound `status`. Without this the unbound handler resolved to its temp dir and every checkout read as absent.
- `last_write_at` uses `symbols.db` mtime (brief allowed either source; no new SQL helper).
- Watcher of a just-indexed explicit path reports `running` because `index --path` loads that checkout; test asserts the real behavior.

**IMPACT**
Verified: `cargo build`, `status_rebuild` (4), `service::http_api` (9), `cli_execution_tests` (37), `global_targeting` (17), `cargo nextest run -p xtask` (179) all green. Dogfooded `workspace status` and `workspace rebuild --path .` under `JULIE_HOME=~/.julie-dogfood`.
