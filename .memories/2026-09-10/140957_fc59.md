## Task 10: vectors in facts, brute-force scan

### WHAT
- `julie-facts`: `encoder` and `vectors` tables, `EncoderRow`, `VectorRow`, writer `set_encoder` (the one documented DELETE: a new encoder identity empties `vectors`) and `store_vectors`; reader `encoder`, `vectors_for_encoder`, `vector_count`.
- `julie-index`: `VectorSet` (row-normalized matrix, `scan` = dot products + partial sort, `bind` rebinds keys to `SymbolId` on every publish), loaded by `CheckoutStore` at build and at `publish_vectors`; `StoreStatus.vector_count`; `search/similarity.rs` and `search/hybrid.rs::vector_search` run on the scan; hybrid fails closed with `SEMANTICS_NOT_READY` when the encoder row differs from the query encoder.
- `julie-pipeline`: embedding pipeline reads symbols from the `Graph`, skips symbols the `VectorSet` already holds, writes through `CheckoutStore::store_vectors`, publishes once per run. Deleted `begin_/publish_/store_embeddings_for_generation`, `file_indexer.rs`.
- `julie-core`: deleted `database/{vectors,embedding_generation*,memory_vectors}.rs`, the vec0 table creation, and `sqlite-vec`/`zerocopy` deps.
- Tools: semantic search pass, deep_dive similarity (0.5), fast_refs semantic fallback (0.2, spawn_blocking) all use the snapshot vectors.
- Readiness (`src/request_engine/semantic_store.rs`): encoder row present and vector count > 0; exit code 4 kept.
- Tests: un-ignored 4 backend_param tests and the spawn_blocking formatting test; ported hybrid_search_tests (33) and m1_challenger_tests (6); deleted generation/revision tests.

### WHY
The facts store is blob-keyed and has one writer; vectors belong next to the symbols they describe. A brute-force scan over ~10k rows costs 22 ms in debug, so no ANN index or sqlite-vec is needed.

### HOW
- `ids: Vec<Option<SymbolId>>` so a vector row whose blob is no longer in `paths` stays in the matrix but never scores.
- `publish_vectors` reloads from facts once per pipeline run instead of per batch.
- `store_vectors` takes no `MutationGuard`; the pipeline runs outside the apply path and the facts writer is single-threaded.

### IMPACT
- Semantic search, deep_dive similarity, and fast_refs fallback work end to end on the snapshot.
- Parked src test modules (`index_embedding_tests`, `native_semantic_*`, `semantic_m1_challenges`, `semantic_request_contract`, `health/checker_test`) still wait on the lead.
- Watcher re-embed on file change was removed with the old per-file embedding path; the pipeline run covers new blobs on the next run.
