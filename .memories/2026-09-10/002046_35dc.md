## Phase 2 Task 5: symbols.db migrations deleted

### WHAT
Deleted `crates/julie-core/src/database/migrations/` (1130 lines, versions 1-32) and the migration-step tests. `initialize_schema` now creates every table, including the five that only migrations used to create (`schema_version`, `embedding_config`, `tool_calls`, `symbol_vectors`, `memory_vectors`), and writes `LATEST_SCHEMA_VERSION` (32, now in `schema.rs`). `SymbolDatabase::new` opens an existing database as-is. `SEMANTIC_INDEX_ENGINE_VERSION` ends with `+schema=32`, and `index` also checks `schema_version_matches()`, so a database at any other schema is deleted and rebuilt, never migrated.

### WHY
Design section 6.1: derived indexes are disposable. Migrations for derived state were a class of coordination code the machine-service design removes. `registry.db` keeps its migrations; it is not derived.

### HOW
Parallel batch A with Task 4 under parallel-lead-commit; lead reviewed the working tree and staged only Task 5's files. `PRAGMA foreign_keys = ON` moved to `SymbolDatabase::new` because it is per-connection.

### IMPACT
Old indexes rebuild once on the next `index`/startup. Follow-ups recorded in the SDD ledger: `src/external_extract/metadata.rs` message still says "migrate"; `startup_repair_plan.rs` checks only the engine string (which now carries the schema number).
