## Task 7: seed a new checkout from a sibling index

**WHAT**: `manage_workspace open` / `index` on a checkout with no `symbols.db` now copies the index of a registered sibling checkout (same `git rev-parse --git-common-dir`), rebinds the per-workspace state rows (`workspaces`, `index_engine_state`, `projection_states`), and runs the existing incremental scan so only files whose blake3 hash differs are re-extracted.

**WHY**: machine-service design section 7 — a new git worktree of a known repo should not index from scratch.

**HOW**:
- `crates/julie-core/src/workspace/git_identity.rs`: `git_common_dir(root)`.
- `src/tools/workspace/indexing/seed.rs`: `SeedReport`, `sibling_checkout` (registry rows with status ready, same common dir, newest `last_indexed`), `copy_dir`, `seed_if_index_missing`, `seed_from_sibling` (WAL checkpoint the sibling, copy db + tantivy, rebind rows, then `index_workspace_files(force=false)`).
- `commands/index.rs`: `handle_index_command_reporting` returns `(CallToolResult, Option<SeedReport>)`; `open.rs` appends the `Seeded from ...` line.
- Tests: `src/tests/tools/workspace/seed.rs` (fixtures/seed/a and b: 6 shared, 2 differing files -> copied 6, re-extracted 2, removed 0, search on b finds a shared-file symbol), `crates/julie-core/src/tests/git_identity.rs` (real `git worktree add`).

**IMPACT**: Real-tree measurement (Julie repo, 1289 files, debug build): from-scratch 35.9 s vs `Seeded from ...: 1289 files copied, 0 re-extracted, 0 removed in 14025 ms`. The standalone CLI has no `open` and no registry, so seeding only runs through the service/MCP path.
