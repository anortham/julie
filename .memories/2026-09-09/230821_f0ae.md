## Phase 2 Task 1: every runtime is the writer

### WHAT
Deleted every "am I the leader?" branch in the handler, request engine, workspace commands, and the workspace runtime phase machine. `LeadershipState` now has only `leader(guard)`, `leader_in_process()`, `none()`, and `is_in_process()`; `is_leader`, `is_follower`, `follower()`, `dynamic()` are gone. `RuntimePhase` is `Owner { epoch }` | `Failed { code }`. The follower promotion probe loop and `DEFAULT_PROBE_INTERVAL` are gone. `RequestRuntime::check_access` and `RequestFailure::follower_read_only` are gone (exit code 4 stays for semantics/busy).

### WHY
One machine service process owns every workspace handler through `RuntimeFactory`, so there is one writer per checkout. Task 2 deletes the lock types as a pure type removal once no branch asks about leadership.

### HOW
- Kept the leader arm at each of the 19 call sites; deleted the follower arm.
- Watcher starts for every bound workspace (`start_file_watching(true)`); startup catch-up and recreated-Tantivy repair run unconditionally.
- `register`/`remove`/`refresh`/`index` no longer refuse for ownership reasons.
- `SourceEditCoordinator::apply` lost its `is_follower` parameter; the follower refresh-hint helpers were dead and deleted.
- Deleted nine leadership test files; moved the five leadership-free constructor/storage tests into `src/tests/core/handler/inprocess_handler.rs`.
- Judgment call: `RuntimeFactory::create_bound_runtime` still acquires `leader.lock` and uses `LeadershipState::leader(guard)` because `acquire_writer_permit` builds the `OwnerEpoch` from that guard; `AlreadyHeld` is now an internal error instead of a follower. `LeadershipState::none()` stays for non-in-process constructors because `is_in_process()` gates the bounded read envelope, not leadership.
- Fixed a stale assertion in `failed_edit_leaves_no_partial_edits_or_corrupted_files` (product emits `EDIT_CONFLICT`, test expected `TOOL_ERROR`; mismatch predates this task).

### IMPACT
`cargo build` green; `cargo nextest run --lib tests::request_engine` 19/19; `cargo nextest run --lib tests::core::handler` 76/76. Task 2 can delete `LeadershipState`, `DaemonLockGuard`, `OwnerEpoch`, `WriterPermit`, `PublicationLock` without touching behavior.
