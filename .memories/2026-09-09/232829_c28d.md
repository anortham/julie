## Task 2: deleted leader lock, epochs, permits, publication lock, host slots

**WHAT**
- Deleted `leader_lock.rs`, `ownership.rs`, `publication_lock.rs`, `host_slots.rs` (julie-core), `src/leadership.rs`, `src/external_extract/lock.rs`, `src/registry/discovery.rs`, and the seven test files that proved cross-process fencing.
- Survivors of `ownership.rs` (`PublicationStamp`, `TantivyCommitPayload`, `SourceCheckState`, `needs_projection_recovery`) moved to `crates/julie-core/src/workspace/projection_stamp.rs`.
- `JulieServerHandler::acquire_writer_permit` replaced by `acquire_mutation_guard(workspace_id) -> MutationGuard<'static>`; every `permit: &WriterPermit<'_>` is now `_guard: &MutationGuard<'_>` (startup, index command, recovery, watcher dispatch and handlers).
- `LeadershipState` replaced by a plain `in_process: bool` on the handler.
- `RuntimePhase::Owner` has no epoch; `IndexScheduler` has no admission pool; watcher `start_watching` takes no epoch.
- Force reindex removes the whole in-process index root under the gate.
- Also removed the Tantivy rebuild flock (`tantivy.julie-rebuild.lock`) in julie-index so `indexes/<id>/` holds only `db/` and `tantivy/`.

**WHY**
Phase 2 of the machine-service design: one process owns every workspace handler, so cross-process coordination is dead code. `mutation_gate` is the only serialization.

**HOW**
Miller `trace` on each lock type, then top-down deletion so the tree compiled at each step. TDD: new test `index_root_holds_only_db_and_tantivy_after_index` was red on HEAD (`publication.lock` + `tantivy.julie-rebuild.lock` present) and is green now.

**IMPACT**
- `grep DaemonLockGuard|OwnerEpoch|WriterPermit|PublicationLock|IndexJobPermit|leader.lock|workspace_leader_lock` over src/crates/xtask returns nothing.
- Verified: `cargo build`, julie-runtime `tests::watcher_mutation_gate` (8), `tests::request_engine` (19), the new layout test, `cargo nextest run -p xtask` (179), and the lead's flagged test `test_fast_search_startup_workspace_id_first_request_succeeds_without_primary_bind`.
- Docs still mention `leader.lock` (docs/OPERATIONS.md, CLAUDE.md); not in Task 2 scope.
