## v8 audit: explicit workspace targeting approved

- **WHAT:** User approved requiring a workspace path or ID on every workspace-specific MCP call. Terminal CLI commands retain current-directory defaults.
- **WHY:** The stdio shim injected its startup cwd, so plugin-cache or /tmp launches silently selected and indexed the wrong directory. Central HTTP already has no session workspace.
- **HOW:** Remove shim cwd/env fallback, preserve global workspace listing/status, teach open(path) then pass workspace ID/path on every content/edit request. Three Sol workers are implementing routing/singleton, HTTP protocol validation, and deployment corrections in deployment-story.
- **IMPACT:** Launch directory becomes irrelevant to MCP targeting. No push/release authorized. Lead approved one OS-held service.lock exception to enforce one service per JULIE_HOME; no stale-lock recovery or new dependency.

Verified design facts: rmcp 3.0.1 supports 2026-07-28, NeverSessionManager and server/discover. Server-side default_mcp_headers masks invalid modern requests and is being removed; pinned SDK already validates modern headers when supplied correctly.
