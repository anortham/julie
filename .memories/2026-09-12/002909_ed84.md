## WHAT

Audited and repaired the v8 deployment path across Julie and `~/source/julie-plugin`. Julie now requires explicit workspace targeting in MCP documentation; packaging supports macOS checksums, preserves valid sidecar metadata, and validates release inputs; `sync-plugin` resolves the main repository through Git common-dir from arbitrary linked worktrees. Restored the standard Codex `mcp.json` and Antigravity `mcp_config.json` plugin declarations now that launch cwd cannot select a workspace. Added `docs/findings/2026-09-11-v8-architecture-audit.md` with the requested architecture diagram and release boundary.

## WHY

The stdio shim previously injected cwd or `JULIE_WORKSPACE`, allowing plugin-directory launches to route calls into the plugin checkout. The release script also assumed GNU `sha256sum` on macOS and repacked a sidecar manifest whose referenced README/LICENSE no longer existed. Worktree sync guessed the sibling from the checkout path and failed from `.worktrees/deployment-story`.

## HOW

Workspace guidance now distinguishes `workspace` on search/navigation/editing calls from `path`/`workspace_id` on `manage_workspace`, with global list/status exempt. Packaging falls back to `shasum -a 256`, preserves README/LICENSE, and renames the metadata file `sidecar-package-manifest.json`. A PATH-isolated behavioral test executes the real packaging script and validates every manifest path exists. `default_plugin_root` uses `git rev-parse --path-format=absolute --git-common-dir` with a normal path fallback, tested using a real temporary linked worktree outside `.worktrees`. Release CI rejects tag/package version mismatch or missing versioned notes before builds.

## IMPACT

Harness launch directories no longer participate in routing, both portable plugin formats can ship their MCP declaration, macOS release packaging has a native checksum path, and the release workflow cannot silently mislabel a binary or publish boilerplate notes. The lead still owns the full gate and live release-candidate verification.
