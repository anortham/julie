## Plan 3B independent cold initialization

### WHAT

- Replaced `RuntimeFactory` bound-runtime map entries with key-local `RuntimeSlot` values containing an optional initialized `RequestRuntime`.
- Added deterministic request-engine tests for cold/warm independence, same-key initialization, and cancelled initialization retry.
- Updated Plan 3 acceptance and the worker verification ledger.

### WHY

The previous bound initialization awaited handler construction, workspace recovery, and repair while holding the global runtime-map write lock. A cold checkout therefore blocked requests for already warm checkouts.

### HOW

- Install or retrieve an empty slot under the map lock, drop it, then hold only that slot while creating and publishing a runtime.
- Failed or cancelled creation leaves the slot empty; a later request retries. Counts inspect populated runtime values rather than slots.
- The cold/warm test failed on `7925798d` and passed after the slot change. Same-key and retry tests are approved baseline characterization/non-regression cases because the old global lock already serialized one initialization and avoided publishing failures.

### IMPACT

Warm checkouts remain responsive while a different checkout starts. Plan 3C can reuse the same key-local slot for teardown and retention; it must not add a second owner or remove empty slots in this slice.
