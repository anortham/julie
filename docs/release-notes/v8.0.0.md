# Julie v8.0.0

Major release. One machine service per developer machine replaces the per-session daemon. Semantic search is on by default. The native sidecar ships inside every archive.

## Summary

- `julie-server` with no arguments is now a small stdio shim. It starts the machine service when none runs and forwards MCP traffic to it.
- One service process owns every workspace index on the machine. There is no leader lock, no per-workspace lock file, and no read-only session.
- Search with no `backend` runs semantic symbol search for natural-language queries when the workspace has vectors. It runs lexical search otherwise.
- `julie-semantic-sidecar` 0.1.0 is packed beside `julie-server` in every release archive. Julie finds it with no configuration.
- The plugin repo `anortham/julie-plugin` ships at 8.0.0 with one install path per harness.

## Machine service

- Start: any MCP client that runs `julie-server` starts the service on first use. The service listens on localhost and mints a new bearer token on every start.
- Control: `julie-server service status`, `julie-server service stop`, `julie-server service restart`. `status` prints a JSON document with every open checkout, the embedding child, and the log path.
- Idle exit: the service exits after 30 minutes with no traffic. MCP requests count as traffic. `JULIE_SERVICE_IDLE_SECS` overrides the limit in seconds. `JULIE_SERVICE_IDLE_SECS=0` disables idle exit.
- Endpoints: Streamable HTTP MCP at `/mcp`, a JSON API at `/api/<tool>`, `/status`, and the dashboard at `/`.
- Stdio shim: the shim forwards each tool call without deriving a workspace from its process environment. Workspace-bound calls require an absolute path or registered workspace ID. When the service goes away, the shim reconnects once. When the reconnect fails, the shim answers with a JSON-RPC error and keeps reading stdin.
- Storage under `$JULIE_HOME` (default `~/.julie`):
  - `indexes/<id>/facts.sqlite` and `indexes/<id>/tantivy/` per checkout.
  - `registry.db` per machine.
  - `service.json` while the service runs.
  - `service.lock`, held by the single owning process; the file may remain after exit.
  - `logs/julie-service.log.<date>` for the service log.
- `facts.sqlite` replaces `symbols.db`. It is never migrated. A schema or engine version mismatch deletes `indexes/<id>/` and reindexes the checkout.
- `manage_workspace open` on a checkout that shares a git common dir with a registered workspace seeds from that sibling. It copies blobs and fact rows by hash, extracts missing blobs, rebuilds `tantivy/`, and runs the incremental scan.
- `manage_workspace` operations are `index`, `list`, `open`, `remove`, `refresh`, `health`, `rebuild`, `status`, `recover_edit`, and `dashboard`. `rebuild` deletes the checkout index and runs a full index.
- The tool catalog is ten tools. Compact output is the default. `fast_search`, `fast_refs`, `get_symbols`, and `blast_radius` page with `offset` and end with a `next:` line.
- `blast_radius` with no seed reads the working-tree git diff.
- Every tool call writes a `tool_calls` row in `registry.db` with the client, client session, Julie version, duration, and result count.

## Semantic search by default

- The service spawns one `julie-semantic-sidecar` child and shares it across every open checkout. The child speaks NDJSON over stdio. There is no broker and no Python runtime.
- Julie looks for the sidecar beside `julie-server` first, then in `~/.cache/julie-semantic/bin/`, then on `PATH`. The release archive puts it beside `julie-server`, so no setup is needed.
- The model is `bge-small-en-v1.5-f32`. On the 23-case scorecard it scored 21 of 23 top-5. `qwen3-0.6b-f16` scored 6 of 23 and was rejected.
- Vectors live in a `vectors` table in `facts.sqlite`. Search scans them in memory. The scan takes under 1 ms for an indexed checkout.
- Search with no `backend` runs semantic search when the query reads as natural language, is not a file path, and the checkout has ready vectors. The compact header reads `(semantic)`. Any other query, and any query while vectors are not ready, runs lexical search. Explicit `lexical`, `semantic`, and `hybrid` behave as before.
- Evidence: on the 23-case scorecard over ten public repos, lexical MRR is 0.351, hybrid 0.677, semantic 0.848. In the head-to-head run the auto backend scored 18 of 23 top-1 and 20 of 23 top-5 at p50 15 ms.
- Backfill runs in the background at about 10 vectors per second, round-robin across every open checkout. Ten corpus repos took about 45 minutes from cold. Search stays lexical for a checkout until its vectors publish.
- `JULIE_EMBEDDING_PROVIDER` accepts `auto` (native when the sidecar binary is found, else none), `native`, or `none`. The default is `auto`.

## Removed

- The per-session daemon: leader lock, owner epochs, writer permits, publication locks, host slots, and the per-session workspace bootstrap. `mutation_gate::acquire_gate` is the only serialization.
- The Python embedding host, the `julie-embedding-host` binary, and the `uv` requirement. `JULIE_EMBEDDING_PROVIDER=sidecar` and `=ort` return a removal error.
- `symbols.db` and its migrations.
- The `rewrite_symbol` and `rename_symbol` tools. Use `edit_file`.
- The `spillover_get` tool and the continuation store. Results are bounded and end with a truncation line when they exceed the limit.
- The `manage_workspace` operations `register`, `clean`, and `stats`.
- The HTTP-URL MCP registration (`http://127.0.0.1:<port>/mcp?token=<token>`) from the docs. The token changes on every service start. Register the stdio shim instead.
- `bin/install-codex.cjs` from the plugin. The Codex marketplace replaces it.
- The test tiers `nano`, `fast`, `smoke`, `system`, `benchmark`, `reliability`, the `changed` diff mapping, and the 52-bucket manifest. See Test tiers.

## Index and registry hygiene

- The service deletes a checkout index only on a typed facts version mismatch. Every other open failure propagates and names the store directory. The three duplicate delete layers are gone.
- `status` reads every checkout through the non-destructive opener. A status call can no longer delete an index.
- `service restart` waits up to 30 s for the previous pid to exit. Only the owning process removes `service.json`. A zombie pid counts as dead on Linux.
- A cleanup sweep runs once at service start. It prunes dead registry rows and orphan index directories and logs the three counts.
- Tests never touch the developer's `~/.julie`. Cargo sets `JULIE_HOME` to `target/test-julie-home` for every test process.
- Evidence: two live restarts on eleven open workspaces changed no `facts.sqlite` birth time and dropped no vector count. Restart wall time was 7.2 s and 6.5 s.

## Test tiers

Three tiers. Each runs one `cargo nextest run --workspace` pass.

- `cargo xtask test dev`: builds `julie-server`, runs the workspace except the dogfood set, then the ignored `tests::cli::` tests. About 12 s warm.
- `cargo xtask test dogfood`: ensures the search-quality fixture, then runs the dogfood set. About 15 s with the fixture present.
- `cargo xtask test full`: `dev` then `dogfood`. About 26 s warm.

Before this release the batch gate took 50.5 s and the broad gate 94 s without dogfood. The gates now run 2,275 of 2,275 listed tests; 319 tests ran in no bucket before. `xtask/` went from 11,470 lines to 2,233.

## Install

Every install path runs the same launcher and gets the machine service with semantic search. The README Installation section holds the verified command or config block for each harness:

| Harness | Path |
|---|---|
| Claude Code | `/plugin marketplace add anortham/julie-plugin`, then `/plugin install julie@julie-plugin` |
| Codex | `codex plugin marketplace add anortham/julie-plugin`, then `codex plugin add julie@julie-plugin` |
| Antigravity | `agy plugin install https://github.com/anortham/julie-plugin` |
| OpenCode | clone the plugin, run `node bin/install-opencode.cjs`, paste the printed block |
| Hermes | clone the plugin, add the `mcp_servers.julie` block from the README to `~/.hermes/config.yaml` |
| Cursor | clone the plugin, add the `mcpServers.julie` block to `~/.cursor/mcp.json` |

The launch directory does not select a checkout. For every harness, open a checkout with `manage_workspace(operation="open", path="/absolute/project")`, then pass the returned workspace ID on every search, navigation, and editing call. Other `manage_workspace` operations use `workspace_id`; global `list` and `status` are exempt.

Manual: download the archive for your platform, extract it, and register `julie-server` with no arguments as a stdio MCP server. Run `julie-server service status` to check the service.

The plugin ships at 8.0.0. Its SessionStart hook prints the routing instructions from `JULIE_AGENT_INSTRUCTIONS.md`, because Claude Code truncates MCP server instructions when several servers are configured.

## Upgrade notes

- Old daemon state under `~/.julie` is ignored. The v7 `symbols.db` files are never read.
- The first service start reindexes each workspace into `facts.sqlite` and `tantivy/`. This is a full index and takes longer than an incremental update. No action is needed.
- Vectors backfill after the index at about 10 vectors per second, shared across all open checkouts. Natural-language search runs lexical until the checkout's vectors publish.
- Remove any HTTP-URL MCP registration (`http://127.0.0.1:<port>/mcp?token=...`) from your client config. Register `julie-server` with no arguments instead.
- Remove any `uv` or Python embedding host setup. Nothing replaces it; the sidecar is in the archive.
- Update any script that calls `manage_workspace register`, `clean`, or `stats`, or the tools `rewrite_symbol`, `rename_symbol`, and `spillover_get`.
- Update any script that calls a removed `cargo xtask test` tier. Use `dev`, `dogfood`, or `full`.

## Known caveats

- Windows: the running `julie-server.exe` holds an exclusive lock on the binary. Stop the service and close the MCP client before you replace the binary.
- First backfill: ten repos of the evaluation corpus took about 45 minutes. A partial backfill does not resume after a restart; the repair plan schedules embeddings only when a checkout has zero vectors.
- The first natural-language query after a service start runs lexical, because the auto path never waits for the embedding child to spawn. The second query runs semantic.
- Resident memory was 2.9 GB with eleven workspaces open. There is no memory bound on open checkouts yet.
- A service whose `/status` fails on a live pid is not respawned. Run `julie-server service stop`, then start again.
- Every restart logs `Found files not in the store - indexing needed reasons=new_files` for some workspaces and runs a repair pass. Nothing is deleted.
